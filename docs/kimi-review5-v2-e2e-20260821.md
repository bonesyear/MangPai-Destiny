## 2. 失败路径判定（阻塞=有环节静默失败用户零反馈）

正常文本排盘链路四环节逐一判定：

| 环节 | 失败表现 | 用户反馈 | 判定 |
|------|----------|----------|------|
| 解析失败 | ParseError → 「输入有误+示例+HELP」 | 明确 | ✅ |
| 引擎异常 | guard ValueError →「输入有误」；非预期异常 →「排盘失败：…」 | 明确（但 S7 裸 repr，P2-1） | ✅ |
| LLM 超时/失败 | LLMBackendError → 降级前缀 → service 注记降级直出 | 明确 | ✅ |
| 发送失败 | 首次失败 → 兜底重发；双失败 → 仅日志 | 双失败=零反馈 | ⚠️ 见下 |

**判定：无阻塞项。** 唯二零反馈路径均非链路内部静默：
- S9 双发送失败=出口断网级，进程内无解（飞书已拿 200 ack 不会重试，且 mid 已入去重窗）。属基础设施层，需外部监控告警兜底，README 已备案去重外部存储为可选散项。
- S10 非文本消息=不支持的输入类型，非处理失败。建议（不阻塞）：回一行 HELP 提示只收文本命令。

## 4. 输出渲染检查（飞书 Markdown 兼容性）

4 盘不同结构（乾造样例/坤造四柱直排/1900 边界乾/子时界坤）全链输出扫描：语法标记集合恒为 `**加粗**`（支持 ✅）+ `- 列表`（不支持 ⚠️）+ `> 引用`（不支持 ⚠️）；LLM 段另引入 `---`（不支持 ⚠️）与校验违规 `- [L0] …` 列表。报告本身无表格/标题/图片/链接，无超卡片长度风险（样例 630 字）。结论：内容完整，格式符号在飞书端字面残留 = P1-2。
