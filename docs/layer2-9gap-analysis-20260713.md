# 第二层审计：9 个残余 ❌ 架构分析

**日期**: 2026-07-13  
**基线**: 67 例回测 ✅39 / ⚠️19 / ❌9（通过率 58%）

---

## 核心结论

9 个 ❌ 不是 9 个独立 bug，是 **3 条架构主线在 5 个书例上的不同投射**，外加 2 个孤立的单点模板缺口。

Hermes 与 CC 独立分析，结论高度一致。

## 五组分类

### 分组一：主功用串行链而非强度权重（3 例）✅ 已修（2026-07-13）

**根因**：`zuogong_detect.py` 和 `zuogong_confirm.py` 的 primary_work 判定是固定类型优先级的串行链——合>制>化>生>墓——先触发先占。段氏原著有时不区分主次，或虽分主次但依据的是做功信号的**强度**而非**类型**。

**涉及案例**：合用 vs 制用优先级冲突、生用 vs 化用竞争

**建议解法**：串行链 → 强度加权排序（每个做功类型算信号强度分，高分胜出）。需要范式级调整，本轮不做。

**Hermes 原话**：「`zuogong_detect` 是串行规则链，先触发先占，没有『哪个信号更强』的权重排序」

**CC 原话**：「固定链 vs 强度权重——补丁叠补丁：每修一个书例就加一条窄 skip，根因不动」

**实际修复（2026-07-13）**：未整体替换串行链（纯强度模型 MAX 聚合回归 生例一/合例六/墓例四/复例一），改取**保守混合**--串行链为默认，于三个判主功决策点引入信号强度 override，仅翻转强度信号明确的两例，0 回归。仅改 `zuogong_detect.py` + `zuogong_confirm.py`：

1. **化用成局（月干司令透干之印）抗降级**（detect 化用前置校准）：原 `_has_real_zhiyong`（涉日支制用两端皆非印星）即降杀印相生为 auxiliary；现增豁免--月干为印（司令透干化杀为权）时化用成局之力胜于涉日支零星制用，不降级（化例三中堂 己日、月干丙印化年/时甲杀，虽寅克丑涉日支制用，主功仍化用成局）。坐下印/时上印力弱不豁免；墓用双计去重不豁免。制例三/合例六/墓例一/复例一/复例二月干皆非印，化用仍降级不变。
2. **争合合用让位化用成局**（confirm 主功链头）：日干合两柱同被合（he_actions≥2，日干仅合一干故必同气争合）时合用力分散；化用成局为高层功量，争合合用让位（化例三中堂 己合甲争合，主功化用非合用）。单合（制例三/合例一/墓例三）不受影响。
3. **伤官入墓之生用让位**（confirm 生用分支）：食伤泄秀之伤官/食神若入墓（gan_entombed），泄秀之器受制无力泄秀，生用不当主功，让位予弃干看支之制用（制例二 戊日伤官辛入墓，主功日支寅克丑/戌制用，非辛泄秀生用）。未入墓之食伤泄秀仍居其位（生例一/二/四/合例八/墓例四）。
4. **连珠成势(L5) gate 成势为主功**（confirm assess_work_level）：原 `san_he_formed and gong_shen_ratio>0.7` 即 L5，致 incidental 三合局命虚高（制例二 寅午戌火局成势但主功在寅克丑戌制用，level 5）；现增 `chengshi_primary`（primary_action 为三合局）gate--三合局须本身为命局主功方升至 L5。无测断言 L5，gate 安全。

**结果**：制例二 ❌->✅（primary 制用 弃干看支，level 5->2）；化例三中堂 ❌->✅（primary 化用 杀印相生，level 3->4 化用成局 L4）。853（361+70+422）+101（103 passed/3 xfailed）全绿，67 例 ✅46->✅48 ⚠️19 ❌2->❌0（+2 ✅ / 0 回归）。cat2 gongliang / cat3 xiangfa 不变。

### 分组二：化用三重过滤过严（1 例）✅ 已修

**根因**：化用成局判定需要「月干为印 + 日支冲穿刑破克真实制用目标 + 非入墓」，三层 gate 过窄。

**建议解法**：detect 补坐下印条件、gate 改用强度判主功。中等改动，本轮可考虑。

**实际修复（2026-07-13）**：化例二（戊壬丙壬/申戌寅辰，丙日坐寅木印化壬水杀）四联改动：
1. `zuogong_detect.py` 化用 detect 补「坐下印」条件——`yin_active` 增 `ZHI_WX[day_zhi]==yin_wx`（日支本气印即印星贴身化杀）。
2. `zuogong_detect.py` 化用前置校准 discriminator 收窄——涉日支之制（冲/穿/刑/破/克）两端若有一为印星五行（财冲坏印/印克食伤等印星自身动作），属化用路径内之象而非独立制用结构，不抑制化用；仅两端皆非印星方为真实制用目标（制例三 酉戌穿两端非印火，仍抑制）。新增 `_pos_wx(pos)` 取柱位五行。
3. `zuogong_confirm.py` `_hua_is_chengju` gate 放宽——除月干印外，坐下印（日支本气印）亦成局；但坐下印须「专司化杀」，日支参六合/暗合（合中心）则力归合用非化杀，不构成成局（合例六 庚日坐戌土印但戌参卯戌合，主功合用非化用）。
4. `zuogong_confirm.py` 主功优先级——化用成局前置至生用之前（化杀为权为高层功量，优先于食伤泄秀）；合用/穿制让位逻辑不变。
5. 附带：`verify_mangpai.py` + `objective/verify_mangpai.py` 合化条件 4 测过滤由 `action=='化用'`（化用重定义后兼含杀印相生）改 `type=='合化'`，对齐化用重定义。

**结果**：化例二 ❌→✅（primary 化用）；合例六回归 ✅（合用主功，坐下印合中心不入成局）；化例一/化例三/制例三不变。853+101 全绿，67 例 ✅46 ⚠️19 ❌2（6 IMPROVE / 0 REGRESSION）。余 2 ❌（制例二/化例三中堂）后由分组一保守混合修复（见上）。

### 分组三：层功保守 distrust + 4 带硬切（1 例）

**根因**：段氏原著四层功量是定性判断（「化用成局 → L4 极富极贵」），引擎用加法点栈 + 4 个 score 带硬切。包制信号采用保守策略（distrust 默认不启用），边界案例 ±1 档抖动不可避免。

**建议解法**：包制 distrust 策略有条件翻转 / 引入双 level 对账（work_level + gongliang_level 互验）。中等改动。

**CC 原话**：「把段氏连续定性判断离散成 4 个 score 带，带边界 ±1 档抖动是 quantize 的内生代价」

### 分组四：象法耦合做功 type 字符串（2 例）

**根因**：象法取象依赖 `work_types` 列表中的字符串匹配，而 work_types 本身依赖主功判定的结果。主功变了，象法跟着偏。

**建议解法**：补分支 + 数据表，让象法不完全耦合 primary_work 的 type 标签。局部改动。

### 分组五：单点模板缺口（2 例）⭐ 最易修

**根因**：

1. **过河拆桥**（`caiming.py`）：模板刚性要求 `日支=财 + 宾位有官 + 财生官五行成立 + 宾字制宾官`。段氏原著过河拆桥核心是「宾字合/制桥（宾官）」，引擎窄化为一种结构，且六合对称关系的方向漏检。

2. **学历之神**（`xueli.py`）：硬编码学历之神 = `{印, 食神}` 二元。段氏原著明言「以官杀、印星、食神当学历之神」，官杀也是学历之神，引擎不认。

**建议解法**：
- 过河拆桥：补六合/暗合方向路径（对称合两端都试），放宽「日支必为财」硬前置
- 学历：`学历之神` 集合增补 `官杀`，补「杀制伤官/合杀→高学历」判定分支

**改动量**：局部增补，不涉及架构。是 9 个 ❌ 里性价比最高的两个。
