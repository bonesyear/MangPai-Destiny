## 0. 先行勘误：T2 缺口 1 定性须修正

T2 称子女断法「引擎没有——liuqin 仅父母/兄弟存亡，无子女域」，**与代码现状不符**。
F17 批（快照 `20260817_f17`）已把高级篇 10.2 核心三节立进 `subjective/liuqin.py` 并经
`engine.py:610` 入 `result['liuqin']`，哨兵 `test_f17_xueli_liuqin.py`：

- `detect_zixi_youwu`（子息有无）：无子五标志（星入墓不开/宫空亡穿破/原神被坏/枭神夺食/满盘比劫伤官），M3 总门=≥2 标志共振方断无子（gaoji:14030-14043）。
- `detect_zixi_xingbie`（头胎性别+换象）：口诀统一口径+案例五互证（gaoji:14132-14180），消费 xiangfa_ops.huanxiang。
- `detect_zixi_youlie`（子女优劣）：原神旺衰+星宫有情+三刑腿（gaoji:14229-14276，案例八/九书例哨兵先红后绿）。

**D6a 的真实缺口**（书锚支持但引擎无对应）：
① 子息**应期**（得子/损子/流产的岁运引动）——四书皆有，liuqin 签名无岁运输入；
② **借腹/过继**子息侧标志（liuqin 的 parent_qiyang 只覆盖「自身被送养」视角）；
③ 优劣增补腿「时柱为喜用/忌」（两书明文，liuqin 未含）；
④ 数量/送终——书自证不准或孤锚（见 §4 收档）。

设计取向因此定为：**zinv 新模块只做岁运应期等新维度，消费 liuqin 已有星宫判定，
不重造星宫定位**（重造=与 liuqin `_child_star_cat`/五标志重复建设）。

## 3. 模块设计：subjective/zinv（新）

### 3.1 定位与边界

- **zinv = 子息岁运应期 + 借腹 marker**。不重造星宫定位/有无/性别/优劣（liuqin 已立，zinv 只读消费）。
- R4（时柱喜用腿）与 R5（有无增补腿）属 liuqin 既有函数增补，按 F 批惯例走 liuqin 小改，不进 zinv。
- 分层：subjective/，单向依赖 objective + subjective.liuqin（只读其输出），不反向依赖 engine。

### 3.2 判定维度（按书锚支持度取舍后）

1. `zixi_yingqi_dezi`（得子应期窗，R1）：机制三类——
   - 合动：岁运干支与子息星五行相合（F2 丁壬合）；
   - 开墓：子息星/妻星之墓逢岁运冲开（F2 辰冲戌、F8 口诀）；
   - 制枭：原局有枭神夺食标志（liuqin marker 在场）而岁运合制印星（F1 庚辰运乙庚合）。
   输出：`{'windows': [{'dayun': '庚辰', 'liunian': [...], 'mechanism': '制枭', 'basis': 'gaoji:14087-14107'}], 'desc': str}`。措辞用「得子/孕育之象」，不写性别不写数量。
2. `zixi_yingqi_sunzi`（损子应期窗，R2）：机制三类——
   - 克到位：子息星五行之克星于大运到位（F4 己未运土克癸水）；
   - 合去：流年干合走子息星（F4 戊寅年戊合癸）；
   - 穿引动：岁运引动原局穿倒子息星之结构（F5/F6）。
   输出同构 `windows+desc`。**红线设计**：desc 用「子息星受创/子女宫引动」等中性措辞，字面不含「死/夭/丧」，LLM 侧再由 build_payload `_scrub_death` 统一兜底（修批A 既有机制，zinv 不自建过滤）。
3. `jiefu`（借腹/养子 marker，R3）：日支（妻宫）受穿 + 子息星入时墓 → `{'is_jiefu': bool, 'basis': [...]}`。
4. `summary`：拼接（liuqin.summary 子息段不重复拼接，只述应期与借腹）。

明确**不做**：数量（R7）、送终（R8）、性情（R10）——收档理由见 §4。

### 3.3 输入依赖

| 依赖 | 来源 | 说明 |
|------|------|------|
| 子息星大类/有无 markers | `liuqin.zixi_youwu.child_star_cat` / `markers` | 星定位唯一来源，不重算 |
| 岁运序列 | `objective.dayun.dayun_gz_sequence` + engine 已有 dayun/liunian 供给（D3 批已补 dayun_analysis） | 应期扫描对象 |
| 岁运-原局关系 | `objective.zuogong_detect.detect_relations`（扩展岁运干支参查，仿 yunfan/liunian 既有用法） | 合/冲/穿检测 |
| 墓库开闭 | `objective.muku.analyze_muku` | 开墓机制 |
| 大限 | 复用 yingqi_subj 三要素口径（大限∩大运∩流年命中其二即 commit） | 聚合闸门，仿 F10 模式 |

engine 接线：`result['zinv'] = self._safe_compute('zinv', analyze_zinv, ...)`，签名对齐 analyze_liuqin 惯例（day_gan/gans/zhis/gender/relations/dayun 序列）。

### 3.4 输出 schema 与 LLM 通道

```python
{
  'zixi_yingqi_dezi':  {'windows': [...], 'desc': str},
  'zixi_yingqi_sunzi': {'windows': [...], 'desc': str},   # 引擎内部 marker，措辞中性
  'jiefu': {'is_jiefu': bool, 'basis': [...], 'desc': str},
  'summary': str,
}
```

- **LLM 五维暂不扩**。现五维=性格/事业/财运/婚姻/应期，无子女维；prompts/schools 受保护，扩维须用户拍板。zinv 输出先经 build_payload selector 进特征 JSON（纯数据，同 liuqin 现状），LLM 是否消费子女维留 D6c+ 单独决策。
- 若未来进 LLM：得子窗可入「应期」维锚定行（与 dayun/liunian 锚表同机制）；损子窗默认被 `_scrub_death` 过滤，与 G6 官命 scrub 同型备案（代价可接受）。
- 与 liuqin 衔接点：liuqin 出「原局有没有/好不好」，zinv 出「何时应」。两者键名分域，summary 不互拼。
