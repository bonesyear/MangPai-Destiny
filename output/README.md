# output/ — 评估与批跑工具（工具脚本入库，数据不入库）

> 本目录存放**评估管线工具脚本**与**批跑产物**。`.gitignore` 采用白名单：**仅工具脚本入库，数据文件一律不入库**。

## 入库范围（`.gitignore` 白名单）

| 入库 ✅ | 说明 |
|---------|------|
| `*.py`（顶层） | 评估/批跑/分析脚本（如 `_eval_common.py`、`_llm_batch_*.py`、`_n2_*.py`、`_t3_*.py`） |
| `*.sh`（顶层） | 批跑调度脚本 |
| `*.md`（顶层） | 说明文档 |

| 不入库 ❌ | 原因 |
|----------|------|
| `*.jsonl` / `*.json` | 批跑数据（体积大、可由脚本重跑；含命例数据） |
| `_kang*` | **真实人物案例数据（隐私红线）** |
| 子目录（含子目录脚本） | 白名单仅覆盖顶层 `*.py`/`*.sh`/`*.md`；子目录整体忽略——未来若批跑脚本子目录化需先显式扩白名单，否则会被静默漏入库 |
| `__pycache__` / `*.pyc` | 编译产物 |

## 🔴 隐私纪律（新增文件前必读）

1. **严禁**在脚本中硬编码真实人物的生辰/案例（如 `calc_bazi_full(1992, 10, 9, ...)` 形式）——需要固定命例时，用**公开出版物断例**（`tests/trainset` 或 `tests/heldout` 的 case id）或参数化传入
2. **严禁**在脚本中硬编码 API key / token / 凭证——统一走环境变量（`.env`，永不入库）
3. 新增脚本后检查 `git status`：确认无数据文件被 `git add`（白名单应自动拦截，但要目视确认）
4. 分析产物（含命例数据的 dump）写本目录即可，**不要**试图强制 `git add -f`

## 主要脚本

- `_eval_common.py` — 统一评估框架（runner / 校准四件 / 分层抽样 / engine_fe 检查），H-fix-7 统一
- `_llm_batch_*.py` — LLM 叙述批跑（trainset / retry / analyze / rescore）
- `_n2_*` / `_t3_*` / `_v3_*` / `_w4_*` / `_w5_*` — 历次评估批的三层漏斗（评审/judge/校准）与样张检查
